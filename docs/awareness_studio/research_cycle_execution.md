# Awareness Studio research-cycle execution

Awareness Studio is a local planning and review interface around the canonical
research-cycle ledger. It does not run simulation solvers, make model calls,
download data, promote claims, or authorize releases.

## Authoritative loop

The orchestrator projects its lifecycle into the dedicated SQLite ledger:

`SourceSnapshot → EvidenceRecord → Claim → Hypothesis → ExperimentSpec → RunRecord → ArtifactManifest → ValidationReport → TheoryRevision`

The first five planning records are written with explicit scopes and
limitations. When a solver has not executed, the remaining nodes are not
fabricated. Instead, the ledger records explicit `BLOCKED`, `NOT_IMPLEMENTED`,
or `REVIEW_REQUIRED` events explaining why a run record, artifact manifest, or
validation result is unavailable. An actual `RunRecordV1` remains owned by
`runs/run_record.py`; the research-cycle ledger never replaces it.

The SQLite ledger is authoritative for research-cycle events. The legacy
`events.jsonl` output is retained only as a compatibility projection for
existing consumers. It is not an independent source of state.

## Dry-run and live behavior

Dry-run execution is classified as `PLANNING_ONLY` and
`scientific_evidence: false`. It contains no solver metrics, no synthetic
RunRecord, and no validation PASS. Report and graph files generated by dry-run
are interface/planning artifacts only.

Live execution currently returns `NOT_IMPLEMENTED` and
`scientific_evidence: false`. It does not create a placeholder checksum or
pretend that a simulation completed. If a future execution adapter is added,
it must supply an independently created canonical `RunRecordV1`, its source
provenance, and validation artifacts before those nodes can be linked.

LLM-generated hypotheses or plans, if introduced by a separate adapter, remain
suggestions. The orchestrator has no path that lets a suggestion directly
mutate claims, datasets, artifacts, or release state.

## Status and scientific guardrails

`INCONCLUSIVE`, `BLOCKED`, `FAILED`, `NOT_IMPLEMENTED`, and
`REVIEW_REQUIRED` are distinct states and are preserved in the ledger. A
completed planning loop is not a scientific PASS. Synthetic data cannot become
empirical evidence; proxy measurements cannot become causal claims; metadata
alone cannot establish consciousness, liberation, biological mechanism, or
topology.

All event writes use the ledger's transactional, hash-chained append-only
storage. Repeated deterministic runs are idempotent, concurrent writers use
`BEGIN IMMEDIATE`, and interrupted writes are recovered by SQLite rollback plus
ledger integrity/hash-chain validation. No network access or model calls are
performed by the execution loop.
